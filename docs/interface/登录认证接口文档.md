# 登录认证接口文档

**Base URL**：`/api/v1/auth`  
**认证方式**：双 Token
- `accessToken`：访问业务接口，默认 30 分钟；
- `refreshToken`：刷新 Token，默认 7 天。

除登录、刷新、登出外，`/api/**` 均需：

```http
Authorization: Bearer <accessToken>
```

> 当前默认 `career-trace.auth.enabled=true`。本地联调可临时改为 `false`，此时使用 `career-trace.auth.dev-user-id`（默认 1）。

---

## 1. 登录

`POST /api/v1/auth/login`

**请求**

```json
{
  "nickname": "陈默",
  "password": "123456"
}
```

**响应 200**

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 1800,
    "refreshExpiresIn": 604800,
    "userId": 1,
    "nickname": "陈默"
  }
}
```

**错误**

| HTTP | code | 说明 |
|---:|---:|---|
| 400 | 400 | 昵称或密码为空 |
| 401 | 401 | 昵称或密码错误 |

**演示账号**：`陈默 / 123456`、`林一 / 123456`。  
密码按 MD5 存 `users.password`，仅演示用；生产环境应换 BCrypt/Argon2 并加盐。

---

## 2. 刷新 Token

`POST /api/v1/auth/refresh`

**请求**

```json
{
  "refreshToken": "登录返回的 refreshToken"
}
```

**响应 200**：同登录，返回新的 `accessToken` 和 `refreshToken`。

**说明**

- 旧的 `refreshToken` 刷新后立即作废（简单轮换）；
- 旧的 `accessToken` 不主动作废，到期自然失效；
- `refreshToken` 被登出/轮换后再次使用返回 401。

---

## 3. 登出

`POST /api/v1/auth/logout`

**请求头**

```http
Authorization: Bearer <accessToken>
```

**请求体（可选）**

```json
{
  "refreshToken": "需要同时注销的 refreshToken"
}
```

**响应 200**

```json
{
  "code": 200,
  "msg": "success"
}
```

登出会把 accessToken 和 refreshToken 放入内存黑名单；再次使用返回 401。

---

## 4. 鉴权规则

1. 拦截器只接受 `Authorization: Bearer <accessToken>`；
2. 校验 HS256 签名、`exp`、`type=access`、`uid`；
3. 校验用户是否存在；
4. 校验 accessToken 是否在登出黑名单；
5. 登录/刷新/登出路径不拦截；
6. `OPTIONS` 预检放行。

> 当前黑名单是单机内存实现，重启即清空；生产建议放 Redis 并设置 TTL。
