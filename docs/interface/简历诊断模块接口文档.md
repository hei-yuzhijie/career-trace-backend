# 简历诊断模块接口文档

**版本**：v0.1  
**基础路径**：`/api/v1`  
**Content-Type**：`application/json`（上传接口为 `multipart/form-data`，PDF 导出为 `application/pdf`）  
**认证**：测试环境当前 `career-trace.auth.enabled=false`，`/api/**` 不校验 JWT，统一使用测试用户 `userId=1`；上线前改为 `true`。

> 本模块包含“简历诊断”和“职业经历诊断”。模块设计见 [简历诊断模块说明文档](../req/简历诊断模块说明文档.md)。

---

## 通用约定

### 统一响应体

除 PDF 导出接口外，均返回：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录（仅在鉴权开启时） |
| 404 | 资源不存在 |
| 409 | 状态冲突（如分析中） |
| 500 | 服务端异常 |

### 分页参数

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| page | int | 1 | 页码，从 1 开始 |
| size | int | 10 | 每页条数，最大 50 |

分页响应：

```json
{
  "total": 5,
  "page": 1,
  "size": 10,
  "records": []
}
```

### 异步任务约定

- 上传简历、重新分析返回 HTTP **202 Accepted**；
- 响应 body 仍为统一响应体，`code=200`；
- 前端通过 `GET /api/v1/resumes/{resumeId}` 轮询；
- 建议轮询间隔 2 秒，响应头返回 `Retry-After: 2`；
- 状态：`0 PENDING`、`1 PROCESSING`、`2 DONE`、`3 FAILED`。

### 状态说明

| status | 含义 |
|---|---|
| 0 | 待分析 PENDING |
| 1 | 分析中 PROCESSING |
| 2 | 已完成 DONE |
| 3 | 失败 FAILED |

## 1. 上传简历

`POST /api/v1/resumes`

**Content-Type**：`multipart/form-data`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | file | 是 | PDF/DOCX/TXT/MD，最大 10MB |
| jobId | long | 否 | 目标岗位 ID；传入后“技能匹配”维度按该岗位 JD/标签评估 |

**响应**：HTTP 202

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "resumeId": 12,
    "status": 0,
    "statusText": "PENDING"
  }
}
```

**说明**

- 文件保存到 `storage/resumes/{userId}/{yyyyMMdd}/{uuid}.{ext}`；
- 立即返回，不阻塞分析；
- 同一用户重复上传同一文件且已完成时，直接返回历史详情；
- 正在分析时重复上传返回 `40902`；
- PDF/DOCX 解析失败返回 `50003`。

**错误**

| code | 场景 |
|---|---|
| 40004 | 文件为空、格式不支持、超过 10MB |
| 40902 | 该文件正在分析中 |
| 50003 | PDF/DOCX 解析失败 |

## 4. 重新分析

`POST /api/v1/resumes/{resumeId}/reanalyze`

**响应**：HTTP 202

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "resumeId": 12,
    "status": 0,
    "statusText": "PENDING"
  }
}
```

**说明**

- 仅 DONE / FAILED 可调用；
- 清空旧评分、旧建议、旧记忆候选；
- 重新入队；
- 分析中重复调用返回 `40902`。

---

## 5. 删除简历

`DELETE /api/v1/resumes/{resumeId}`

**响应**：HTTP 200

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "resumeId": 12,
    "deleted": true
  }
}
```

**说明**

- 删除 `resumes`、`resume_advices`、`resume_memory_candidates`；
- 删除本地文件；
- 分析中不允许删除，返回 `40902`。

## 6. 导出 PDF 诊断报告

`GET /api/v1/resumes/{resumeId}/report`

**响应**：HTTP 200，**不是 JSON**

```http
Content-Type: application/pdf
Content-Disposition: attachment; filename="resume-report-12.pdf"
```

**说明**

- 仅 DONE 状态可导出；未完成返回 `40905`；
- 报告包含：文件名、目标岗位、总分、五维得分、总结、优势、建议；
- 中文字体使用 classpath 字体，避免乱码；
- 前端使用 `window.open` 或 `fetch + blob` 下载，不要按 JSON 解析。

**错误**

| code | 场景 |
|---|---|
| 40404 | 简历不存在 |
| 40905 | 简历尚未完成诊断 |

`GET /api/v1/resumes/{resumeId}/memory-candidates`

**响应**：HTTP 200

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "resumeId": 12,
    "candidates": [
      {
        "candidateId": 31,
        "content": "独立负责公众号周更，粉丝从 1.2k 增长到 3.6k",
        "tags": [
          {
            "tagName": "内容策划",
            "category": "skill",
            "proficiency": 3,
            "confidence": 0.92,
            "evidence": "独立负责公众号周更"
          }
```

- 候选只是预览，未确认不写 `memory_items`。

## 8. 确认导入职业记忆

`POST /api/v1/resumes/{resumeId}/confirm-memories`

**请求体**

```json
{
  "candidateIds": [31, 32]
}
```

**响应**：HTTP 200

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "resumeId": 12,
    "imported": 2,
    "skipped": 0,
    "memoryIds": [301, 302]
  }
}
```

**说明**

- 候选必须属于该简历且 `status=0`；
- 每条候选写一条 `memory_items`：
  - `source_type='resume'`；
  - `source_id=resumeId`；
  - `status=1`；
- 标签走 `TagNormalizationService` 归一化，命中已有标签后写 `memory_tags`：
  - `assessed_by='manual'`；
  - `proficiency/confidence/evidence` 取候选；
- 更新候选 `status=1`、`memory_id`；
- 触发 `user_skill_profile` 异步重算；
- 重复确认同一候选直接跳过（幂等）。

**错误**

| code | 场景 |
|---|---|
| 40404 | 简历不存在 |
| 40407 | 记忆候选不存在 |
| 40906 | 简历尚未完成诊断 |

## 9. 职业经历诊断

`GET /api/v1/users/me/career-diagnosis`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| jobId | long | 否 | 目标岗位；不传则做通用职业经历诊断 |

**响应**：HTTP 200

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "source": "MEMORY",
    "targetJobId": 3,
    "overallScore": 76,
    "summary": "内容运营经历与目标岗位匹配度较高，但数据复盘证据不足。",
    "dimensions": [
      {"dimension": "经历完整度", "score": 18, "maxScore": 20, "comment": "记忆覆盖内容/技能/偏好"},
      {"dimension": "成果量化", "score": 14, "maxScore": 20, "comment": "有阅读量与粉丝增长，缺少转化数据"},
      {"dimension": "技能覆盖", "score": 17, "maxScore": 20, "comment": "内容策划/数据复盘覆盖较好"},
      {"dimension": "岗位匹配", "score": 15, "maxScore": 20, "comment": "地点与核心技能匹配"},
      {"dimension": "表达结构", "score": 12, "maxScore": 20, "comment": "部分记忆缺少背景"}
    ],
    "strengths": ["内容策划有可量化成果", "地点与目标岗位一致"],
    "gaps": ["缺少 A/B 测试证据", "数据分析只有结论，没有过程"],
    "suggestions": ["补充一个 A/B 测试项目或课程作品"]
  }
}
```

**说明**

- 分数由代码计算，LLM 只负责总结/建议；
- 传 `jobId` 时复用岗位匹配算法；
- 不传 `jobId` 时“岗位匹配”给通用基础分，响应中 `targetJobId=null`；
- 不写数据库，可选用 Redis 缓存 5 分钟。

## 错误码汇总

| code | 场景 | 建议提示 |
|---|---|---|
| 40004 | 文件为空/格式不支持/超 10MB | 仅支持 pdf/docx/txt/md，且不超过 10MB |
| 40404 | 简历不存在 | 简历不存在或已删除 |
| 40407 | 记忆候选不存在 | 候选不存在或已处理 |
| 40902 | 简历正在分析 | 正在分析中，请稍候 |
| 40905 | 简历未完成诊断 | 请等待诊断完成后再导出 |
| 40906 | 简历未完成诊断（导入） | 请等待诊断完成后再导入 |
| 50003 | 简历解析失败 | 简历解析失败，请检查文件格式 |
| 50004 | 诊断失败 | 诊断服务暂时不可用，请稍后重试 |

## 状态与轮询示例

```text
POST /api/v1/resumes                     → 202 { resumeId:12, status:0 }
GET  /api/v1/resumes/12                  → 200 { status:1 }
GET  /api/v1/resumes/12                  → 200 { status:2, overallScore:82, ... }
GET  /api/v1/resumes/12/memory-candidates → 200 [...]
POST /api/v1/resumes/12/confirm-memories  → 200 { imported:2 }
GET  /api/v1/resumes/12/report            → 200 application/pdf
```
