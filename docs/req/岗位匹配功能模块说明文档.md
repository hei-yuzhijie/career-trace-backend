# 岗位匹配功能模块说明文档

**模块定位**：把用户职业记忆经大模型抽取为归一化标签，与 BOSS 抓取岗位的标签做“硬门槛过滤 + 加权匹配”，输出可解释的推荐分与归因明细。

**核心链路**：

```
职业记忆 → 大模型抽标签 → tag_aliases 归一化 → memory_tags 落库
                                                      ↓
                                        异步聚合 skill → user_skill_profile
                                                      ↓
岗位 JD → 大模型抽标签 → tag_aliases 归一化 → job_tags 落库
                                                      ↓
                             推荐计算：排除过滤 → location 硬过滤 → 加权求和 → 归因输出
```

---

## 一、数据模型总览

| #    | 表名                 | 作用                            | 写频率   |
| ---- | -------------------- | ------------------------------- | -------- |
| 1    | `users`              | 用户占位表                      | 低       |
| 2    | `companies`          | 公司主数据（BOSS 公司去重）     | 低       |
| 3    | `tags`               | 标签字典，全系统唯一定义        | 低       |
| 4    | `tag_aliases`        | 标签别名，大模型输出归一化入口  | 中       |
| 5    | `jobs`               | 岗位主数据                      | 中       |
| 6    | `memory_items`       | 职业记忆原文                    | 中       |
| 7    | `memory_tags`        | 记忆 ↔ 标签，带极性/熟练度/证据 | 高       |
| 8    | `job_tags`           | 岗位 ↔ 标签，带权重/要求等级    | 高       |
| 9    | `user_skill_profile` | 用户 skill 聚合，推荐读表       | 异步更新 |

**ER 关系**：

```
users 1 ── n memory_items 1 ── n memory_tags n ── 1 tags 1 ── n tag_aliases
                                                        ↑
companies 1 ── n jobs 1 ── n job_tags n ────────────────┘
                                  ↓
                        user_skill_profile（仅 skill 类聚合）
```

```sql
CREATE TABLE tag_aliases (
  id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  tag_id      BIGINT UNSIGNED NOT NULL,
```

```sql
CREATE TABLE memory_tags (
  memory_id    BIGINT UNSIGNED NOT NULL,
```

```sql
CREATE TABLE job_tags (
```

## 三、核心流程

### 3.1 记忆入库 → 异步打标签

1. 用户新增记忆，写 `memory_items`，返回 `taggingStatus=PENDING`。
2. 事务提交后投递异步任务（`@Async` 线程池；后续可替换为 MQ），调用大模型抽取标签。失败按 3.6 重试。
3. 大模型返回 `[{name, category, polarity, proficiency, confidence, evidence}]`；system prompt 来自 `prompts/memory-tagging.md`。
4. **归一化**（`TagNormalizationService`）：
   - 先按 `tag_aliases.alias` 的归一化文本精确匹配（忽略大小写、空格、标点）；
   - 再剥离“不考虑 / 希望 / 能接受 / 岗位”等语气词后匹配；
   - 仍未命中则算拼音 slug，查 `tag_aliases.alias_slug` / `tags.slug`；
   - 最终仍未命中才新建 `tags` + `tag_aliases`（生产建议改为进人工审核队列）。
5. 写 `memory_tags`（先删旧标签再插入，`ON DUPLICATE KEY UPDATE` 兼容覆盖）。
6. 更新 `memory_items.updated_at`，标记 DONE；每次成功打标都异步重算 `user_skill_profile`（幂等，顺带清理已删除的 skill）。

### 3.2 岗位入库 → 打标签

1. BOSS 抓取写 `companies`（按 `external_id` 去重）、`jobs`（按 `source + external_id` 去重）。
2. 异步任务对 `jd_text` 调大模型抽标签，同样过 `tag_aliases` 归一化。
3. 写 `job_tags`，`weight` 由大模型判断（必备 1.0 / 加分 0.5），`required_level` 仅对 skill 类赋值。
4. 硬性条件（经验年限、学历）不单设字段，统一抽成 `seniority` 类标签，靠 `weight=1.0` 表达“必备”。

### 3.3 推荐计算（两段式 + 语义混合）

> 详细公式、示例和复杂度见 `docs/algorithm/岗位推荐算法说明.md`。本节只描述模块设计。

#### 3.3.1 第一段：排除过滤 + location 硬过滤

```sql
-- 1) 用户排除标签（polarity = -1）
SELECT mt.tag_id
FROM memory_tags mt
JOIN memory_items mi ON mi.id = mt.memory_id
WHERE mi.user_id = ? AND mi.status = 1 AND mt.polarity = -1;

-- 2) 若用户有 location 标签，则岗位必须命中至少一个 location 标签
SELECT DISTINCT j.id
FROM jobs j
JOIN job_tags jt ON jt.job_id = j.id
JOIN tags t      ON t.id = jt.tag_id AND t.category = 'location'
WHERE j.status = 1
  AND jt.tag_id IN (:user_location_tag_ids);
```

实现补充：

- `city` 参数在 SQL 中先收窄岗位池。
- 如果岗位没有 `job_tags` 的 location 标签（数据缺失），用 `jobs.city` 与用户 location 标签名兜底匹配，避免误杀。
- 第一段结果作为第二段候选集；`filterSummary` 返回 `excludedByPolarity`、`excludedByLocation`、`candidateCount`。

#### 3.3.2 第二段：结构化分 + 语义分

不再使用一条大 SQL 做 `SUM(weight × confidence)`，因为需要按岗位归一化、处理等级差、扣分和语义分：

```text
totalWeight = Σ job_tags.weight（只统计 weight > 0）
semanticAvailable = Embedding 已配置且本次调用成功
structuredMax = semanticAvailable ? 85 : 100

对每个 job_tag：
  命中非 skill / requiredLevel=0:
    contribution = structuredMax × weight × confidence / totalWeight
  命中 skill 且 requiredLevel>0:
    levelFactor = 1 / 0.5 / 0.2 / 0（等级差 0/1/2/≥3）
    contribution = structuredMax × weight × confidence × levelFactor / totalWeight
  未覆盖必备项（weight=1.0）:
    contribution = -structuredMax × weight × 0.50 / totalWeight
  未覆盖加分项（weight=0.5）:
    contribution = -structuredMax × weight × 0.25 / totalWeight
  命中用户排除项（仅 explain）:
    contribution = -structuredMax × weight × 1.0 / totalWeight

structured = clamp(Σ positive + Σ negative, 0, structuredMax)
semantic   = 15 × clamp((cosine - 0.55) / 0.30, 0, 1)   // 语义可用时
score      = clamp(structured + semantic, 0, 100)
```

设计要点：

1. **按 `totalWeight` 归一化**：标签更多、JD 更长的岗位不会天然高分。
2. **未覆盖项按权重扣分**：不是旧版固定 `0.16`，必备项和加分项扣分不同。
3. **skill 等级差**：用户有该技能但等级不足时，仍给部分分，同时把缺口抽到 `gap`。
4. **语义分只做辅助**：上限 15 分，不能推翻硬过滤；Embedding 不可用时自动降级为纯结构化 100 分制。
5. **语义文本**：用户侧由“标签名 + 熟练度 + evidence”拼接；岗位侧由“标题 + 城市 + 公司 + JD + 岗位标签”拼接。
6. **缓存**：按内容 SHA-256 在进程内缓存用户/岗位向量；不新增表。Embedding 失败后默认 60 秒内不重试。
7. **测试约束**：模块联调时 Embedding/DeepSeek 调用合计不超过 5 次；单元测试用假客户端，不访问外部 API。

### 3.5 提示词与归一化约束

1. 大模型标签抽取的 system prompt 放在 `src/main/resources/prompts/memory-tagging.md`，通过 `career-trace.llm.tag-prompt` 加载。
2. Prompt 中明确要求：`name` 只保留标签本体，否定项用 `polarity=-1` 表达，例如“不考虑销售岗”→“销售 / -1”，“希望有带教”→“带教 / 1”。
3. Java 侧再做一层归一化：别名文本精确匹配 → 语气词剥离 → 拼音 slug 匹配 → 新建标签。避免把“不考虑销售岗”直接建成新标签。
4. 未命中的标签目前自动建 `tags + tag_aliases`；生产建议改为 `pending_tags` 人工审核/合并，避免同义词污染。
5. 后续模块（岗位 JD 打标、简历解析等）的约束文档统一放在 `prompts/`，命名 `<模块>-<任务>.md`。

### 3.6 异步打标重试

| 项 | 规则 |
|---|---|
| 最大尝试次数 | 3 次（首次 + 2 次重试），由 `career-trace.llm.tag-max-attempts` 控制 |
| 可重试错误 | 连接超时、读超时、429、5xx、模型返回 JSON 解析失败 |
| 不重试错误 | 401/403、参数错误、未配置 API Key |
| 退避 | 第 n 次失败后等待 `tag-retry-backoff-ms × n`，默认 800ms、1600ms |
| 成功 | 覆盖 `memory_tags`、更新 `memory_items.updated_at`、状态 DONE、触发 skill 画像重算 |
| 失败 | 状态 FAILED，保留旧标签（如果是 retag），用户可再次调用 `POST /memories/{id}/retag` |
| 幂等 | 每次成功写入前删除旧 `memory_tags` 再插入，按 `memory_id + tag_id` 覆盖 |

## 四、关键注意点

1. **归一化是推荐能否匹配的前提**。大模型输出必须经 `tag_aliases.alias_slug` 精确查，禁止直接 `INSERT tags.name`。未命中的新标签建议进人工审核队列，而不是自动建——否则 `tags` 表会被同义词污染。

2. **`location` 是硬门槛，不是权重项**。不要把“想留在杭州”的权重调高来模拟过滤，必须在 SQL 第一段用 `IN` 硬过滤，否则上海岗位会以低分混进列表。

3. **`polarity` 只放用户侧**。`job_tags` 不设极性，排除逻辑全部由 `memory_tags.polarity = -1` 驱动，第一段先剔除。

4. **`proficiency` 只有 skill 和部分 experience 有意义**，其他类别存 0。聚合表 `user_skill_profile` 只收 `category = 'skill'`，`experience` 类不进聚合，推荐时实时读 `memory_tags`。

5. **`user_skill_profile` 异步更新**。记忆新增/修正后，投递重算任务；推荐读到的是“上次聚合结果”，允许分钟级延迟。任务需幂等（按 `user_id + tag_id` 覆盖）。

6. **用户修正熟练度 = 覆盖**。`memory_tags` 用 `ON DUPLICATE KEY UPDATE`，并把 `assessed_by` 置为 `manual`；不要新增一条修正记录，否则聚合会重复计数。

7. **岗位硬性条件走 `weight`**。`experience_required`、`education_required` 不单设字段，抽成 `seniority` 类标签，`weight = 1.0` 表示必备。这样“3-5 年”和“本科”都能被同一套匹配逻辑处理。

8. **`jobs` 去重用 `(source, external_id)`**。BOSS 重复抓取时 `ON DUPLICATE KEY UPDATE` 更新 `jd_text` 和 `status`，不新建行。

9. **同义标签的子串歧义**。`alias_slug` 是精确匹配，不做 `LIKE`。如果同时存在“大小周”和“大小周没问题”，必须拆成两个 alias 分别指向不同 tag，不能靠子串判断。

10. **排除项不要混进 `SUM`**。第一段过滤完再算分，避免负向标签参与加权导致分数失真。

11. **语义分是辅助项，不是硬门槛**。Embedding 只加 0–15 分，不能把地点不符或命中排除项的岗位拉回列表；Embedding 失败时自动降级为结构化 100 分制。

12. **测试环境暂时关闭 JWT**。`career-trace.auth.enabled=false` 时所有 `/api/**` 请求使用 `career-trace.auth.dev-user-id`，上线前必须改回 true，并设置强随机 `JWT_SECRET`。

13. **提示词是配置，不是代码**。标签抽取约束在 `src/main/resources/prompts/memory-tagging.md`，修改 prompt 等同于修改线上行为，需要同步更新本文档、接口文档和测试用例。

14. **相似度阈值需要按模型标定**。当前 `0.55–0.85` 来自 `text-embedding-v3` 在种子数据上的实测；换模型或换领域语料后应重新标定，避免 semantic 分失去区分度。
